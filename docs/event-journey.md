# イベント当日（9/29・恵比寿）の整合性

会場に **本人・Omi・スタックチャン・MacBook**、自宅に **Mac Studio**。
MacBook とスタックチャンが繋がっている状態で、Omi との連動が成立するかを詰めた（2026-09-23）。

---

## 結論

**成立する。ただし4つの制約を、先に受け入れておく必要がある。**

```
【恵比寿のバー】                          【自宅】
  本人 + Omi（首元）                        Mac Studio
     │ Bluetooth（1本だけ）                  （届かない）
  スタックチャン ←→ MacBook
```

---

## 制約1：Omi は1台としか繋がれない

ファームの作りで**同時接続は1台**。MacBook が繋いでいる間、他の誰も繋げない。

- **守りとしては好都合。** 会場で他人が Omi に接続できない
- **代わりに、繋いでいる間は本体への録音が止まる**（ファームは「未接続のときだけ貯める」作り）

### つまり：イベント中のライフログは残らない

| やりたいこと | できるか |
|---|---|
| Omi を口元のマイクにして、その場で使う | **できる** |
| 同時に、その日のライフログを本体に貯める | **できない**（どちらか一方） |
| イベント後に振り返る | イベントモードを切ってから、改めて録る必要がある |

**判断が要る**: 当日のライフログを残したいなら、イベントモードを一度切る時間を作る。

## 制約2：自宅の Mac Studio は使えない

Tailscale を使わない決定（2026-09-21）により、**会場から自宅には届かない**。

自宅にあるもの: 要約、関所の32B判定、夜の対話、Vault への書き出し。
**当日はすべて使えない。** MacBook だけで完結する範囲に限る。

| 工程 | 当日 |
|---|---|
| ①記録・⑤⑥の対話 | MacBook で可能 |
| ③文字起こし | MacBook で可能（`whisper-large-v3-turbo`） |
| ④要約・⑤関所（32B） | **不可**（メモリが足りない）→ 7B に落ちる |
| Vault への書き出し | **当日はやらない。** 帰宅後に回す |

## 制約3：MacBook の処理が重なる

当日 MacBook が同時にやること:

- DJ機材からの入力（USB・DDJ-FLX2）
- スタックチャンの制御（ゲートウェイ）
- Omi からの音声受信（Bluetooth）
- その場での文字起こし（Whisper）

**DJ と文字起こしが同時に走るのは未検証。** 通しリハで必ず確かめる。
落ちたときの切り分け: **DJ が主役**。文字起こしが重ければ、Omi 連動を切る。

## 制約4：コードが会場で壊れないようにした（対処済み）

関所の判定は 32B が既定だった。MacBook で動かすと **18GB のダウンロードが始まる**。

→ `gate.py` に**モデルの梯子**を入れた（2026-09-23）。
**手元にすでにあるものを選び、無ければその場で落としに行かない。**

| 2 | Qwen2.5-7B（MacBook 向け） | 20% |
