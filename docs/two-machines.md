# 2台目の Mac を、計算用に借りるときの決めごと

2026-09-21。**数か月だけ手元にある2台目の Mac Studio（M4 Max / 36GB）**をどう組み込むか。

---

## 原則：**いつでも切れる形にする**

返す日が来る機械なので、**返した瞬間に止まる作りにしない**。

```
毎日の流れ（吸い出し → 文字起こし → 要約 → 関所）
    → 1号機だけで完結する。2号機が無くても動く

重い実験（大きい教師モデル・LoRA 学習・大量評価）
    → 2号機があれば速い。無ければ1号機で遅く動くだけ
```

実装: `pipeline/common.py` の `ollama_host(prefer_remote=True)`。
2号機が見えなければ、**黙って1号機に落ちる**。

---

## 役割分担

| | 1号機（本番） | 2号機（計算用・借り物） |
|---|---|---|
| 個人データ | **すべてここ**（音声・文字起こし・要約） | **一切置かない** |
| 処理 | 吸い出し、文字起こし、要約、関所の最終判断 | 大きいモデルの常駐、LoRA 学習、作り物データの生成、評価 |
| 返却時 | — | **消すものが無い**（モデルの重みとキャッシュだけ） |

### なぜ個人データを置かないか

1. 返却時の後始末が要らない。消し忘れても実害がない
2. 「使ってよいのは自分の3台だけ」という決めごとを曖昧にしない
3. **返した瞬間に動かなくなる作り**を避けられる

---

## つなぎ方

**TB4 のケーブルで十分**（TB5 は不要）。理由:

| 流れるもの | 大きさ | TB3/4 での時間 |
|---|---|---|
| 判定1回の問い合わせ | 約2KB | 1ミリ秒未満（判定の計算は84ms） |
| 1日分の音声 | 最大500MB | 約1秒 |

**通信は少しもボトルネックにならない。**
TB5 が効くのは「1台に載らない巨大モデルを2台に分割して動かす」場合だけで、
そのときも効くのは帯域より**遅延**のほう。

### 手順（戻ったときに10分）

1. 2台を TB4 ケーブルでつなぐ
2. Thunderbolt Bridge（macOS 標準）で両機に固定IPを振る（例 169.254.10.1 / .2）
3. 2号機で Ollama を外向きに起動（`OLLAMA_HOST=0.0.0.0 ollama serve`）
4. 1号機で `export OLLAMA_REMOTE=http://169.254.10.2:11434`

**それだけ。** 切りたくなったら、環境変数を外すかケーブルを抜く。
