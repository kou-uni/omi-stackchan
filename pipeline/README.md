# 1日を取り込んで、知見にするまで

```
Omi ──① 吸い出し──▶ raw.bin ──② 切り分け──▶ 時刻つきの WAV
                                                  │
                                            ③ 文字起こし（手元の Whisper）
                                                  ▼
                                            transcript.json
                                                  │
                                            ④ 詳細要約（手元の LLM）
                                                  ▼
                                             summary.md
                                                  │
                                         ④.5 **固有名詞をイニシャルに**
                                                  ▼
                                          summary.anon.md
                                                  │
                          ⑤ 関所: 知見の抽出 → 自動チェック → **本人の承認**
                                                  ▼
                                        ThoughtLog Vault（insights/ ほか）
                                                  │
                                    ⑥ 夜、スタックチャンが問いかける
                                       （`night.py` → 実機が声で返す）
```

**①〜④は安全領域の中だけで動く。** 外に出るのは⑤を通ったものだけ。

## 置き場所

既定は `~/Lifelog/<日付>/`。環境変数 `LIFELOG_HOME` で変えられる。

- **iCloud と同期するフォルダには置かない**（書類・デスクトップ）
- 将来は暗号化ボリュームに移す。そのときも `LIFELOG_HOME` を変えるだけ
- **このリポジトリには入れない**（`.gitignore` 済み）

## 使い方

```sh
# ① 吸い出し（実機から。tools/drain.py）
python tools/drain.py ~/Lifelog/2026-09-22/raw.bin

# ② 時刻つきの区切りに分ける
python pipeline/decode.py 2026-09-22

# ③ 文字起こし（ネット不要）
python pipeline/transcribe.py 2026-09-22

# ④ 詳細要約（手元の LLM）
python pipeline/summarize.py 2026-09-22

# ④.5 固有名詞をイニシャルに置き換える（対応表は安全領域から出さない）
python pipeline/anonymize.py 2026-09-22

# ⑤ 知見の候補を作る → review.md を見て、要らないものを消す
python pipeline/gate.py 2026-09-22
#    残したものを Vault へ
python pipeline/gate.py 2026-09-22 --approve

# ⑥ 夜、スタックチャンに問いかけさせる
python pipeline/night.py 2026-09-22           # 台本を見るだけ
python pipeline/night.py 2026-09-22 --speak   # 実機に喋らせる
```

## 夜の対話（night.py）

その日の要約から、**問いを1つと、明日の備忘**だけを作って喋らせる。

```
[thinking]
定義が固まる前に特化させるのは、どのタイミングで決めるべきだったんだろう？
[pause=1.0]
Aさんには来週中に設計案を送るようにしよう。実機でマイクの感度も確認してね。
```

**なぜ問いを1つだけか**: まとめを読み上げられても聞き流して終わる。
**問われると、答えようとして考える。** 記録の価値が出るのはそこ。

**喋らせる前にも関所を通す。** 家の中の実機でも、通さない情報は通さない。
実機に送るのは読み上げる文だけで、要約も文字起こしも送らない。

実機側の口（stackchan-lab、実測）:
```
POST http://127.0.0.1:8779/api/speak?k=<鍵>   {"script": "..."}
鍵: ~/.config/stackchan/panel-token
記法: [happy] で表情 / [pause=1.5] で間 / 改行で区切り
声: VOICEVOX（ローカル）
```

## 関所（gate.py）が見ているもの

**形**（文字列の見た目）と**意味**（手元の判定モデル）の二重。
どちらも完全ではない前提で両方を通し、**最後は必ず本人が `review.md` を見る**。

判定モデルの詳細 → [SYSONE.md](SYSONE.md)（Jev の考え方を手元で再現したもの。1判定179ms）

| 見つけるもの | 例 |
|---|---|
| 鍵・トークンらしき文字列 | `sk-…` `ghp_…` `AKIA…` `xoxb-…` |
| パスワードらしき記述 | 「パスワード: …」 |
| 電話番号 / メールアドレス | |
| 住所らしき記述 | |
| **固有名詞の残り** | 匿名化しきれなかった人名・組織名 |

検証済み（2026-09-21・作り物のテキストで）: 6種類すべて検出し、知見だけの文は素通しした。

**意味のチェック**（120判定で実測）: 他人の私的情報・秘密情報・場所の3つを、**取りこぼし0件**で検出。
無駄な印は 25% / 0% / 6%。詳細と限界は [SYSONE.md](SYSONE.md)。

**承認後も、書き出す直前にもう一度チェックする。** 引っかかったものは書き出さない。

### 人名は「判定」ではなく「変換」で処理する

本人の基準（2026-09-21）: **固有名詞が出たらだめ、イニシャルならよい**

「他人の事情が書いてあるか」を判定させようとすると、**人でも判断が揺れる**。
実際、ペルソナ96件にラベルを付けてもらったところ、人名が出てくる27件のうち
16件が「はい」、11件が「いいえ」で、**ほぼ同じ構造の文が両方に分かれた**。

→ 判定をやめて、**要約の段階で名前をイニシャルに置き換える**（`anonymize.py`）。
関所は「**置き換え残りがないか**」だけを見る。これなら機械的に決まり、揺れない。
対応表（誰がAか）は**安全領域から出さない**。
